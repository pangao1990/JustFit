# 《装满这一箱》小游戏备案自查清单

## 名称与主体

- [ ] 后台小游戏名称为“装满这一箱”。
- [ ] 首页及全部备案截图内能看到“装满这一箱”。
- [ ] 签署文件内游戏名称与后台完全一致，没有书名号、空格或副标题差异。
- [ ] 备案主体、管理员和签署人信息与小程序后台一致。
- [ ] 签名或盖章清晰、完整、可识别。

## 类目与内容

- [ ] 游戏类型选择“休闲类”。
- [ ] 页面自动生成的内容类型为“益智”。
- [ ] 场景说明不少于30字，且与截图一致。
- [ ] 玩法说明不少于50字，且准确说明目标、操作、胜负条件。
- [ ] 货币、商城、道具三个实际存在的系统均已填写，说明各不少于30字。
- [ ] 明确说明金币不可充值、提现、交易或兑换现实物品。
- [ ] 明确说明补给商店不接入微信支付、不销售现金商品。
- [ ] 未填写游戏中不存在的兑换码、VIP、体力、红包等系统。

## 截图

- [ ] 场景截图至少3张。
- [ ] 玩法截图至少3张。
- [ ] 每个已填写系统至少1张截图。
- [ ] 同一张截图只用于一个备案模块，不在场景、玩法或不同系统之间重复提交。
- [ ] 全部截图来自微信开发者工具中的真实小游戏运行画面。
- [ ] 全部截图为完整竖屏画面，无底部裁切、无滚动拼接。
- [ ] 全部截图尺寸一致，为514×1146。
- [ ] 每张图片在60KB–5MB之间，格式为PNG/JPG/JPEG。
- [ ] 截图清晰，无鼠标指针、开发者工具面板、后期说明文字或额外水印。
- [ ] 截图中的关卡、金币、商店、道具等内容与填写说明一致。

## 文件签署与预览

- [ ] 管理员本人微信完成二维码扫码签署。
- [ ] 下载或预览签署文件，确认名称、主体、签名/盖章无误。
- [ ] 若页面要求补充授权材料，授权链完整且所有文件中的游戏名称一致。
- [ ] 信息预览页逐项复核，没有空白必填项、错别字或截图错位。
- [ ] 最终提交动作由备案负责人在确认全部信息后完成。

## 项目与资料隔离

- [ ] 备案资料仅保存在 `doc/备案材料/`。
- [ ] `doc/` 已被排除在小游戏上传代码包之外。
- [ ] 截图辅助代码已从正式游戏源码移除。
- [ ] 原玩家存档已恢复。
- [ ] `npm run validate` 已通过。
